# Contributing to Cybersecurity-Projects

Thanks for your interest in improving this repository.

## Good contributions

Contributions are especially welcome when they improve:

- defensive security functionality
- documentation and examples
- input validation and error handling
- accessibility and browser demos
- testing and maintainability
- Blue Team / SOC learning value

## Safety and scope

Please keep contributions educational, defensive, and authorized-use focused. Do not add credential theft, stealth/persistence, destructive behavior, malware deployment, or instructions intended for unauthorized access.

## How to contribute

1. Fork the repository.
2. Create a focused branch for one change.
3. Keep the change small and clearly documented.
4. Test the affected project locally when possible.
5. Open a pull request explaining what changed, why it helps, and how it was tested.

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Existing behavior is preserved unless the PR intentionally changes it.
- [ ] Documentation is updated when needed.
- [ ] No secrets, tokens, private data, or generated credentials are committed.
- [ ] Security-related functionality is intended for defensive, lab, CTF, or explicitly authorized use.

Thanks for helping make the portfolio more useful to cybersecurity learners and defenders.
